How it works

A transparent, deterministic observation pipeline centered around the Watchtower inspection engine.

01

Your repositories

Configured repositories you own or authorize.

02

Watchtower scan

Runs on temporary runners or local editor.

03

package.json + lockfiles

Resolves exact installed package graphs.

04

npm registry + OSV advisories

Cross-references releases and CVE records.

05

Dashboard / Telegram / VS Code

Reports factual intelligence where you need it.

Watchtower reads dependency data and reports facts. Your repositories are never modified.

What it catches

Accurate dependency observability across every state of your package graph.

Security vulnerabilities

OSV-based advisories, severity levels, and verified fixed-version guidance.

Major updates

Breaking semver jumps isolated clearly from routine releases.

Routine updates

Minor and patch releases with no known security issues.

Deprecated packages

Official npm registry deprecation warnings and end-of-life notices.

Monorepo mismatches

Conflicting version constraints across workspaces in pnpm or npm monorepos.

Daily change history

Chronological diffs of changes recorded since the previous scan.

Your dependencies. Your repository. Your choice.

✓

No Watchtower backend or paid hosting required: Runs entirely on GitHub infrastructure or your local machine.

✓

Temporary GitHub runners: GitHub Actions executes on ephemeral runners that terminate immediately after scan completion.

✓

Read-only GitHub tokens: Private repository access requires only read access stored securely in GitHub Secrets.

✓

GitHub Pages disabled by default: Dashboards are optional and private historical JSON remains inside your repository.

✓

Private Docker mode: Run the dashboard strictly on localhost with no external network publishing.

Setup

Fork the template, configure your projects, and run your first scan in minutes.

1

Fork the template

Copy the repository to your personal or organization GitHub account.

2

Add your repositories

Define the repositories to track in config/projects.yml.

3

Run your first scan

Trigger GitHub Actions manually or wait for the scheduled daily cron.

config/projects.yml YAML 
settings:
  publicDashboard: false

projects:
  - id: my-app
    name: My App
    source:
      type: github
      repository: https://github.com/you/my-app.git
